## Что выяснилось на защите других групп

Это пересказ источников, а не команды из документов. В расшифровке есть ошибки
распознавания; опираться на повторяющиеся ясные тезисы преподавателя:

1. Сначала деятельность потребителя и противоречие, затем назначение продукта.
2. Качество — измеримая степень удовлетворения потребности пользователя.
3. Нужно вывести функции для достижения назначения и раскрыть их процессами.
4. Из процессов выводятся частные функционально-технические требования.
5. Архитектура — облик всей системы: необходимые содержательные компоненты,
   связи, интерфейсы, принципы функционирования и развития. Одних «front/backend»
   недостаточно.
6. Технический проект раскрывает каждый принципиальный компонент в конкретные
   программные модули, информационные структуры и условия взаимодействия.
   Существенные связи архитектуры должны сохраняться и уточняться.
7. По каждому модулю нужен предметный результат разработки: входы, выходы,
   правила, ошибки и проверяемое задание, чтобы было ясно, что писать.
8. ПМИ проверяет достижение назначения и качества целой системы. Прохождение
   внутренних тестов отдельных модулей этого само по себе не доказывает.
9. Важна сквозная цепь «потребность/проблема → гипотеза → решение → функция →
   процесс → компонент → модуль → испытание → свидетельство → решение о качестве».
10. Большой объём технических деталей без этой связи оценку не обеспечивает.

Обсуждение в чате дополнительно подчёркивает связь «Гипотезы → Решение → Тесты»
и принципы функционирования и развития.

## Как продолжать

Сначала `git pull`, затем определить реальные инструменты нового компьютера.
Для чтения PDF ничего устанавливать не нужно. Для содержательных правок менять
`src/build_documents.py` и связанную модель `src/project_model.py`.
`python src/build_documents.py` перезаписывает DOCX, поэтому последующие изменения
только в Word не сохранятся при повторной сборке.

Порядок сборки и проверки находится в README. `src/fonts.py` ищет шрифты на
Windows и Mac; иные пути задаются переменными BANK_FONT_ARIAL/BANK_FONT_TIMES.
На Windows экспорт PDF автоматизирован через установленный Word; на Mac поля
можно обновить и экспортировать документ из Word. После изменений снова проверить
пагинацию, подписи, шрифты PDF и соответствие рисунков модели.

Исходные стандарты, полный чат/расшифровка и чужой образец в репозиторий не
публиковались. Их существенные требования и структура сохранены здесь и в
нормативной справке; банковские сущности можно сверить с BD_labs.
