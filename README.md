# Банковская система

Информационная система учёта клиентов, счетов, банковских карт, переводов и кредитных
договоров. Автор: **Салихов Р. Р.**, группа **М8О-309БВ**.
Преподаватель: **Д. В. Кубраков**.

Редакция от **23.11.2026**. Записка описывает самостоятельный проект банковской
информационной системы. В записке **110 страниц, 36 диаграмм, 35 требований, 25 сценариев**
и восемь приложений А–Е, Ж, И. Основной текст оформлен на А4; крупные схемы —
на А3. Титул заполнен. PDF содержит содержание, закладки разделов и встроенные
шрифты. Памятка занимает 5 страниц; речь на её второй странице — 288 слов.

Постановка начинается с интереса руководителя операционного
направления и противоречия между обслуживанием и ручной сверкой при ограниченном
труде сотрудников. Затем заданы внешнее назначение, общая гипотеза и концепция
качества. Функции, процессы, необходимые программные средства, архитектура,
технические задания и испытания выведены после этого.

И24 сравнивает полный удельный труд ручного способа А и способа Б с программой
на 30 одинаковых обращениях. Предлагаемая норма — уменьшение не менее 20 % при
правильном результате и том же составе исполнителей. Это проектная норма для
согласования, а не измеренный эффект банка. Критическое нарушение исключает
приёмку; без корректной базы сравнения эффект остаётся неподтверждённым.

Сначала прочитать памятку. Для показа открыть раздел 1, затем рисунки **Г.4–Г.5**,
дерево **Б.3**, процесс **В.4**, связность в **Ж**, раскрытие **Д.2/Д.7** и
контракты **И**. Переходы доступны через содержание и закладки PDF.
Точные страницы: Г.4 — 75, Г.5 — 76, Б.3 — 47, В.4 — 64, Д.7 — 87, Ж — 99, И — 102.

## Содержание

Восемь основных разделов: вербальное описание, декларативная модель,
функциональная модель, процессная модель, архитектура, технический проект,
программа и методика испытаний, самоанализ средств моделирования.

| Приложение | Содержание |
| --- | --- |
| А | Документы, лингвистический минимум, модели Чена предметной области и качества, логические модели |
| Б | Контекст, связный первый уровень и общие ресурсы, дерево, пять подробных DFD, словарь 39 потоков, требования |
| В | Спецификации 15 листьев, восемь BPMN с кодами операций и информационными объектами, состояния, ФТТ |
| Г | Облик, обобщённое функционирование, обоснование гипотез, внешнее назначение, концепция качества, интерфейсы и развитие |
| Д | Задания 11 модулям, размещение, раскрытие компонентов, подробная декомпозиция перевода, алгоритмы и запросы |
| Е | Связь гипотез с качеством, процедура получения свидетельств, прослеживаемость, сценарии, данные и форма протокола |
| Ж | Каждый лист → операция → необходимое программное средство → компонент → модуль и обработчик → проверка |
| И | Все 63 поля девяти отношений, 11 детальных контрактов, типы, семантика, кодирование, отказы и примеры JSON |

Предметная модель включает `branch`, `client`, `account`, `employee`,
`bank_card`, `transfer`, `loan` и `loan_schedule`; `audit_event` хранит
историю изменений. На логических схемах показаны все 12 внешних ключей.

Денежный результат перевода — `completed`; повтор не создаёт второе списание.
Кредитная часть фиксирует утверждённый договор и план, а фактическое погашение
подтверждает кредитная служба. Числовые эталоны рассчитаны независимо.

Результат репозитория — технический проект и документация. Приёмочные
испытания банковского ПО заданы как последующий этап. Выполненные проверки
относятся к документам, графике, связям модели и арифметическим эталонам.

## Продолжение на другом ноутбуке

```sh
git clone https://github.com/qwertyvich/IT-project.git
cd IT-project
```

Сначала прочитать [CONTEXT.md](CONTEXT.md), затем [AGENTS.md](AGENTS.md).
В них сохранены последнее задание, смысл замечаний преподавателя, принятые
решения и состояние работы. Прежняя тема «БанкПеревод» отменена; старые
документы доступны только в истории Git.

Для просмотра PDF зависимости не требуются. Для правок документа можно
открыть DOCX в Word. Сборка генератором перезаписывает оба DOCX; изменения
следует вносить в генераторы `src/`, чтобы они сохранялись при сборке.

## Исходники и воспроизведение

```text
src/project_model.py       единая модель, требования, функции, модули, проверки
src/business_case.py       данные постановки, критериев и обеспечения операций
src/report_content.py      введение, восемь основных разделов, заключение и источники
src/diagram_catalog.py     состав и подписи 36 диаграмм
src/dfd_model.py           типизированные потоки и проверка границ декомпозиции
src/dfd_figures.py         код DFD
src/process_figures.py     BPMN с операциями и объектами данных
src/additional_figures.py  назначение, качество, детальный компонент
src/draw_figures.py        построение графических моделей
src/diagram_tools.py       примитивы Чена, DFD, BPMN и других схем
src/render_figures.mjs     Graphviz и растровый экспорт
src/build_documents.py     сборка записки и приложений
src/defense_guide.py        объяснения и речь на три минуты
src/specifications.py      словарь полей, интерфейсы, OpenAPI и примеры
src/quality_metrics.py     расчёт внешнего критерия и неопределённого результата
src/document_layout.py     оформление Word
src/render_word.ps1        обновление полей и PDF через Word на Windows
src/check_project.py       проверка структуры и эталонов
src/check_reproducibility.py повторная генерация и сравнение хешей
figures/                  DOT, SVG и PNG для всех диаграмм
contracts/                машиночитаемые сетевые контракты OpenAPI 3.1
docs/                     применённые стандарты и результаты просмотра
Готовая работа/            PDF, DOCX и архив исходников
```

Нужны Python 3.12+, Node.js 22+, Arial и Times New Roman. Версии библиотек
зафиксированы в `requirements.txt` и `package.json`.

```sh
python -m pip install -r requirements.txt
npm install
python src/draw_figures.py
node src/render_figures.mjs
python src/build_documents.py
python src/check_project.py
python src/check_reproducibility.py
```

Пути к шрифтам Windows и macOS выбираются в `src/fonts.py`. Если шрифты стоят
в другом месте, указать файлы через `BANK_FONT_ARIAL` и `BANK_FONT_TIMES`.
Точное совпадение хешей между разными ОС не предполагается: оно зависит
от версий шрифтов и рендерера. На исходной машине все 87 генерируемых файлов
совпали при повторной генерации.

После новой сборки DOCX нужно обновить содержание и поля в Word, экспортировать
PDF и проверить страницы. На Windows с установленным Word это делает
`src/render_word.ps1` (параметры `-InputDocx`, `-OutputPdf`, `-Update`). На Mac
поля обновляются в Word, затем документ сохраняется как PDF. Готовые PDF уже
проверены; повторная сборка для чтения не нужна.
