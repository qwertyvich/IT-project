Вариант 5. Учёт клиентов, счетов, банковских карт, переводов и кредитных
договоров. Автор: **Салихо Р. Р.**, группа **М8О-309БВ**.
Преподаватель: **Д. В. Кубраков**.

В записке 83 страницы, 30 диаграмм, 33 требования, 23 сценария испытаний
и все шесть приложений А–Е. Основной текст оформлен на А4; крупные схемы —
на А3. Титул заполнен. PDF содержит содержание, закладки разделов и встроенные
шрифты. Памятка занимает 4 страницы; текст речи — 292 слова с запасом на показ схем.

Главная цепочка: потребность → противоречие → гипотеза → функция → процесс →
содержательный компонент → конкретный модуль → испытание → свидетельство →
решение о качестве. Отдельно определены принципы функционирования и развития.

Для показа за три минуты: **с. 63 — Г.3**, **с. 61 — Г.1**,
**с. 69 — Д.2**, **с. 77 — Е.1**. Сначала прочитать памятку для защиты.

## Содержание

Восемь основных разделов: вербальное описание, декларативная модель,
функциональная модель, процессная модель, архитектура, технический проект,
программа и методика испытаний, самоанализ средств моделирования.

| Приложение | Содержание |
| --- | --- |
| А | Документы, лингвистический минимум, модели Чена предметной области и качества, логические модели |
| Б | Контекстная DFD, первый уровень, дерево функций, пять подробных DFD, требования |
| В | Спецификации всех 15 листьев, шесть BPMN, состояния, ФТТ |
| Г | Облик, обобщённое функционирование, обоснование гипотез, интерфейсы и развитие |
| Д | Задания всем 11 модулям, размещение, раскрытие компонентов, алгоритмы, конкуренция, последовательность, контракты и запросы |
| Е | Связь гипотез с качеством, процедура получения свидетельств, прослеживаемость, сценарии, данные и форма протокола |

Сохраняются все шесть сущностей исходных лабораторных: `branch`, `client`,
`account`, `bank_card`, `transfer`, `loan`. Добавлены `employee` и
`loan_schedule`; `audit_event` — служебный журнал. На логических схемах
показаны все 12 внешних ключей.

Денежный результат перевода — `completed`; повтор не создаёт второе списание.
Кредитная часть фиксирует утверждённый договор и план, а фактическое погашение
подтверждает кредитная служба. Числовые эталоны рассчитаны независимо.

Результат репозитория — технический проект и документация. Приёмочные
испытания банковского ПО заданы как последующий этап. Выполненные проверки
относятся к документам, графике, связям модели и арифметическим эталонам.

## Продолжение на другом ноутбуке

```sh
git clone https://github.com/qwertyvich/IT-project.git
cd IT-project
```

Сначала прочитать [CONTEXT.md](CONTEXT.md), затем [AGENTS.md](AGENTS.md).
В них сохранены последнее задание, смысл замечаний преподавателя, принятые
решения и состояние работы. Прежняя тема «БанкПеревод» отменена; старые
документы доступны только в истории Git.

Для просмотра PDF зависимости не требуются. Для правок документа можно
открыть DOCX в Word. Сборка генератором перезаписывает оба DOCX; изменения
следует вносить в `src/build_documents.py`, чтобы они сохранялись при сборке.

## Исходники и воспроизведение

```text
src/project_model.py       единая модель, требования, функции, модули, проверки
src/diagram_catalog.py     состав и подписи 30 диаграмм
src/draw_figures.py        построение графических моделей
src/diagram_tools.py       примитивы Чена, DFD, BPMN и других схем
src/render_figures.mjs     Graphviz и растровый экспорт
src/build_documents.py     содержание записки и памятки
src/document_layout.py     оформление Word
src/render_word.ps1        обновление полей и PDF через Word на Windows
src/check_project.py       проверка структуры и эталонов
src/check_reproducibility.py повторная генерация и сравнение хешей
figures/                  DOT, SVG и PNG для всех диаграмм
docs/                     применённые стандарты и результаты просмотра
Готовая работа/            PDF, DOCX и архив исходников
```

Нужны Python 3.12+, Node.js 22+, Arial и Times New Roman. Версии библиотек
зафиксированы в `requirements.txt` и `package.json`.

```sh
python -m pip install -r requirements.txt
npm install
python src/draw_figures.py
node src/render_figures.mjs
python src/build_documents.py
python src/check_project.py
python src/check_reproducibility.py
```

Пути к шрифтам Windows и macOS выбираются в `src/fonts.py`. Если шрифты стоят
в другом месте, указать файлы через `BANK_FONT_ARIAL` и `BANK_FONT_TIMES`.
Точное совпадение хешей между разными ОС не предполагается: оно зависит
от версий шрифтов и рендерера. На исходной машине все 72 генерируемых файла
совпали при повторной генерации.

После новой сборки DOCX нужно обновить содержание и поля в Word, экспортировать
PDF и проверить страницы. На Windows с установленным Word это делает
`src/render_word.ps1` (параметры `-InputDocx`, `-OutputPdf`, `-Update`). На Mac
поля обновляются в Word, затем документ сохраняется как PDF. Готовые PDF уже
проверены; повторная сборка для чтения не нужна.
