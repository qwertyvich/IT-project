# Банковская система

Технический проект информационного обеспечения обслуживания физических лиц в отделениях банка: клиенты, счета, карты, внутрибанковские переводы, утверждённые кредитные договоры и документы. Автор — **Салихов Р. Р.**, группа **М8О-309БВ**; преподаватель — **Кубраков Д.В.**

- [Подготовка к защите — DOCX](<Готовая работа/Защита за 3 минуты и пояснения.docx>).
- [Исходники проекта — ZIP](<Готовая работа/Исходники проекта.zip>) — модели, генераторы, рисунки, контракты и проверки.

Текущая редакция — **concise**, по новому указанию пользователя и ориентиру «Онлайн-кинотеатр» (Cinema). Записка занимает **46 страниц: 23 основной части и 23 приложений**. В ней семь глав, 27 нумерованных заголовков H1/H2, 20 схем, восемь логических таблиц и пять приложений А–Д. Четыре подробные схемы остаются на А3. Оглавление занимает один лист. Основной текст — Times New Roman 14 пт, интервал 1,5; таблицы — 12 пт.

Для сборки принят контрольный предел 49 страниц, из них не более 27 страниц приложений, чтобы удерживать объём рядом с образцом. Объём и хеши последней проверенной сборки фиксирует [verification_concise.json](src/verification_concise.json). Продолжения увеличивают число физических частей таблиц, но не число логических таблиц.

## Смысл проекта

Интерес организатора — правильно завершать обращения при заданном составе сотрудников. Ручные сверки необходимы для сохранности учёта, но отнимают ресурс обслуживания. Проектная гипотеза связывает автоматизацию повторяемых проверок и документов с сокращением полного труда без потери правильности.

Цепочка обоснования: **интерес организатора → назначение и качество → функции и процессы → необходимые программные средства → компоненты и модули → измерения, свидетельства и решение**. Критерии результата, полного труда, времени и проверяемости определяются до выбора функций.

В полной модели девять отношений, включая служебный аудит, 64 поля, 12 внешних ключей и 11 программных модулей. Печатная ER содержит все поля. Полные задания и контракты сохранены в исходниках; в записке оставлен необходимый печатный набор.

| Приложение | Содержание |
| --- | --- |
| А | Логическая модель данных и декларативная модель оценивания качества |
| Б | Контекст, первый уровень и ресурсы DFD, дерево функций, подробные переводы и договоры |
| В | Общий процесс, клиентский маршрут, карты, переводы, договоры, сведения и состояния |
| Г | Облик, раскрытие компонентов в модули, алгоритмы, детальный компонент переводов и задания 11 модулям |
| Д | Условия, действия, ожидаемые результаты и свидетельства девяти групп испытаний; форма протокола |

Перевод меняет остатки, конечное состояние и аудит одним исходом; повтор использует прежние ключ и ID. Потеря подтверждения COMMIT означает неизвестный вызывающему исход и требует сверки. Договор распознаётся по неизменяемому `contract_ref`; совпавший повтор сохраняет первоначального автора и план.

Результат репозитория — технический проект и документация. Проверки подтверждают согласованность моделей, рисунков, спецификаций, документов и расчётных эталонов. Реализация комплекса и её приёмочные испытания — последующий этап. Нормы 20 %, 30 пар и 120 секунд предложены для согласования; измеренный эффект банка не заявлен.

## Исходники и продолжение работы

- [CONTEXT.md](CONTEXT.md) — актуальная постановка и сохранённые решения; [AGENTS.md](AGENTS.md) — правила дальнейших изменений.
- [concise_content.py](src/concise_content.py) — семь глав, введение, заключение и список заголовков.
- [build_concise.py](src/build_concise.py) — печатная записка, задания модулей и ПМИ.
- [concise_catalog.py](src/concise_catalog.py) — состав и нумерация 20 печатных схем.
- [build_concise_guide.py](src/build_concise_guide.py) — двухстраничная памятка с переходами по фактическому PDF.
- [module_tasks.json](contracts/module_tasks.json), [openapi.json](contracts/openapi.json) — полные задания модулей и сетевые контракты.

Аудиты прежних редакций в `docs/`, их номера страниц и прежние сборщики сохраняются как история и технические исходники. Они не задают текущую печатную структуру. Чужие документы, исходные аудиозаписи и сырьё распознавания в готовый комплект не входят.

## Воспроизведение

Для чтения достаточно PDF. Генерация использует Python, Node.js 22 или новее, Arial и Times New Roman. Пути к шрифтам разрешает [fonts.py](src/fonts.py); при необходимости задаются `BANK_FONT_ARIAL` и `BANK_FONT_TIMES`. Окончательная пагинация и обновление полей выполняются Microsoft Word на Windows через отдельный скрытый COM-сеанс.

Из корня репозитория, в PowerShell:

```powershell
python -m pip install -r requirements.txt
npm install

python src/prepare_concise_figures.py
node src/render_concise.mjs
python src/build_concise.py
python src/finalize_print.py
python src/build_concise_guide.py

$bankProject = (Get-Location).Path
powershell.exe -NoProfile -ExecutionPolicy Bypass -File src/render_word.ps1 `
  -InputDocx (Join-Path $bankProject 'Готовая работа\Защита за 3 минуты и пояснения.docx') `
  -OutputPdf (Join-Path $bankProject 'Готовая работа\Защита за 3 минуты и пояснения.pdf') `
  -Update

python src/check_concise.py
python src/package_sources.py
```

`prepare_concise_figures.py` готовит печатную выборку из кодовых моделей и сохранённых исходных SVG. Если изменены генераторы общих схем, перед подготовкой выборки обновить их:

```powershell
python src/draw_figures.py
node src/render_figures.mjs
```

`finalize_print.py` последовательно обновляет пагинацию и оформляет продолжения таблиц, затем экспортирует основной PDF. Памятка собирается после него: её номера страниц извлекаются из окончательной записки. После пересборки нужно визуально проверить все страницы, особенно переносы таблиц, подписи, оглавление и нижнюю строку титула.

Итоги проверок: [verification_concise.json](src/verification_concise.json), [pagination.json](src/pagination.json), [reproducibility_concise.json](src/reproducibility_concise.json). ZIP создаётся последним: `package_sources.py` включает актуальные исходники, документацию, рисунки и контракты, добавляет хеши и проверяет содержимое архива. Готовые DOCX/PDF публикуются отдельно и в ZIP не дублируются.
